# Visual acceptance criteria for the desktop implementation

The production desktop frontend should be considered visually aligned when:

1. The outer frame has a stylized Pokédex/device feel without consuming excessive workspace.
2. Navigation uses a dark navy sidebar with a clearly highlighted blue active state.
3. Main content uses white/off-white rounded cards rather than flat enterprise tables everywhere.
4. Blue section headers visually group dense PTU information.
5. Pokémon Types, Move Categories, Stats, Item Categories, HP states and validation states use semantic colors.
6. Pokémon and rosters are image-first, making teams recognizable at a glance.
7. Dense sheets use tabs, chips, contextual panels and popovers instead of removing information.
8. The Shop looks like a visual game inventory/shop, not an accounting grid.
9. Windows editors preserve the same visual language while allowing denser mouse/keyboard workflows.
10. GM Override, validation conflicts and incomplete content are visually obvious but not disruptive.

Use `docs/reference/pokemon-ui-design-compliance.md` for the detailed token reference.
